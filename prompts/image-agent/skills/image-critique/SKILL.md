# 图片分析与点评

## 适用与不适用

用于用户想看懂一张或多张已有图片：描述内容、识别视觉风格、分析构图与光线、比较版本、判断优缺点或提出修改建议。这个 skill 的默认结果是文字分析，不生成、不编辑。用户已经明确要求“分析完直接改”时，可以先给简短诊断再进入 edit；用户只想抽取某种风格另起新图时应选 `reference-style-transfer`。

## 专业 brief

提取 `targetAssetIds`、`analysisGoal`、`subject`、`composition`、`camera`、`lighting`、`palette`、`materials`、`typography`、`brandElements`、`strengths`、`issues`、`suggestedChanges`。只描述可见证据；不确定的品牌、人物身份、地点或技术参数要用审慎措辞，不能把猜测写成事实。

## 信息充分度与追问

有可解析图片就直接分析，不要先反问用户想不想改图。用户指定某个维度时聚焦该维度，同时给必要上下文。没有图片却说“分析这张”时，清楚说明目前看不到目标，请上传或从历史中选择。多图比较时按同一套维度并列对照，最后给出适用场景差异，而不是分别写两篇互不相干的描述。

## assistantReply 风格

先给整体判断，再按主体与信息层级、构图与镜头、光线与颜色、材质与细节、文字/logo、可改进点展开。用户只要简单描述时控制长度；用户问专业分析时给足证据。避免空洞评价“很高级、很有氛围”，每个判断都对应可见元素。

## generation.prompt 规则

本 skill 默认不得填写 generation.prompt，`nextAction=discuss`、`generation=null`。只有用户在同一轮明确要求根据分析继续出图或改图，才转交相应生成 skill；此时分析结论应变成可执行的构图、光线、材质和保持项，而不是把点评原文整段塞进 prompt。

## 正例、反例与质量检查

正例：“分析我上传的包装图，重点看构图和文字层级”应直接说明可见证据。“比较刚才两版，哪张产品更突出”应按主体占比、对比、留白和背景竞争度比较。反例：“参考这张配色画咖啡海报”是参考生成；“把这张背景删掉”是编辑。

检查是否真的引用了存在的资产；是否覆盖用户指定维度；是否区分观察与推断；是否识别可见文字/logo；是否给出具体可执行建议；在用户未要求生成时是否严格保持 `shouldGenerate=false`。
